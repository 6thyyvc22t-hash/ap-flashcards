# 応用情報 科目B — 追加・編集・削除できるデジタル単語帳

更新日：2026-11-22

## 構成

- `index.html` — 画面・学習 UI。問題数や本文は一切ハードコードしない。
- `app.js` — 採点、復習、学習記録、問題管理、データ検証。
- `styles.css` — iPad・スマホ向け表示スタイル。
- `questions.json` — 全問題と削除済みの保管データ。初期状態は150問。

## 使用開始（iPad + GitHub Pages）

1. 新しく **Public** リポジトリ `ap-flashcards` を作る。既存のPrivate `my-knowledge-base` を公開しないこと。
2. 4ファイルをリポジトリの最上位に同時にアップロードする。ZIPそのものをアップロードしない。
3. GitHub `Settings` → `Pages` → `Deploy from a branch` → `main` / `(root)` を選択。
4. `https://6thyyvc22t-hash.github.io/ap-flashcards/` をSafariで開く。
5. 共有 → ホーム画面に追加。

> GitHub Pagesの公開URLが有効になるまではエラーになります。GitHub Pagesへのアップロード・公開はユーザー操作が必要です。

## 問題の追加・編集・削除

単語帳の画面下部 **「問題の追加・編集・削除・復元」** から操作できます。

**管理画面の改善（2026-11-23）:** 検索結果は50問で打ち切らず、現在の問題をすべて一覧表示します。枠内の高さ制限もなく、Safariのページ自体をスクロールして確認できます。各問題には「編集」「保管」「完全削除」の操作があります。「保管」は後から復元可能です。「完全削除」は保管を経由せず、一覧のボタン→確認ダイアログの1段階で完全削除できます（IDを retiredIds に保持して再利用しません）。確認を取り消せば削除されません。どちらも、最初はこの端末の未公開下書きであり、全端末へ公開するには questions.json の書き出しとGitHubへの反映が必要です。

1. 追加／編集／削除を実施。削除は `archivedCards` に移動し、後から復元できます。さらに「完全削除」を選ぶと本文を消し、`retiredIds` にIDだけ残して再利用を防げます。
2. **「問題データを書き出す」** から `questions.json` をダウンロード。
3. GitHubリポジトリの既存 `questions.json` を新ファイルで **置換** してコミット。
4. 公開先URLをSafariで再表示すると全端末で新問題が使えるようになります。
5. 最新公開版が反映されたらローカル下書きは自動的に解消されます。

※端末で追加・編集した問題は、GitHubにアップロードするまでは **その端末だけの下書き** です。ChatGPTで既存 `questions.json` の追加・削除を行ってGitHubに反映する運用も可能です。複数端末の下書きを同時編集すると競合するため、編集・公開する端末を一つに決めることを推奨します。

## 安全なID・学習記録の扱い

- すべての問題には不変の `id` を付与。初期カードは `001`〜`150`。
- 追加カードは `nextId`（初期値151）を採番してインクリメント。削除しても番号を再利用しない。
- 問題の単純な誤字修正なら同じIDで編集できる。
- **問い・正答の意味が変わる場合** は削除→新規登録として新しいIDを使う。意味の異なる新問題への成績の誤引継ぎを防ぐ。
- 削除した問題は `archivedCards` へ移動し出題・集計対象から除外。保管中のカードは公開JSONから読むことができるため、本文も公開対象から消したい場合は「完全削除」を選ぶ。過去の成績はIDに紐づいて維持し、復元時に再表示される。
- 正答率は **正解回数 ÷（正解回数＋不正解回数）**。スキップは採点しない。
- ブラウザのローカルストレージに採点結果と端末下書きを自動保存する。公開後の問題変更でも同じ公開URL／ブラウザであれば従来の記録を維持できる。
- 以前の「150問固定版」の学習記録をインポートできる（`ap-kamokuB-150-progress` 形式）。同一オリジンであれば旧ローカルストレージキーからの自動移行も試みる。
- GitHub Pagesへアップロードしても学習記録はGitHubに自動同期されない。他端末へ移る前に **「学習記録を保存（JSON）」→「学習記録を読み込む」** を使う。
- ローカルストレージを消去したり公開URLを変更すると記録を取り出せなくなるため、定期的にバックアップを推奨する。

## JSONのスキーマ

```json
{
  "schemaVersion": 2,
  "deckId": "ap-kamoku-b",
  "title": "応用情報技術者試験 科目B デジタル単語帳",
  "revision": "2026-11-22T23:50:00+09:00",
  "nextId": 151,
  "categories": ["情報セキュリティ", "プロジェクトマネジメント", "サービスマネジメント", "経営戦略", "システム監査"],
  "cards": [{"id":"001","category":"情報セキュリティ","question":"...","answer":"...","explanation":"...","point":"..."}],
  "archivedCards": [],
  "retiredIds": []
}
```

`revision` は公開版更新の識別子。問題の追加・削除をするたびに新しい日時文字列へ更新します。学習記録は同じIDを保持する限り影響を受けません。

# iPad・iPhone間のクラウド自動同期（Firebase）

更新日：2026-11-23。以前の「端末内のみ」の方式を拡張。単語帳は **設定前もローカルで利用可能**。GitHub PagesにアップロードしただけではFirebaseとの同期は始まりません。

## 1. Firebaseプロジェクトを作成する（本人操作が必要）

1. https://console.firebase.google.com/ を開き、Googleアカウントでログインし、「プロジェクトを追加」を押す。
2. 任意のプロジェクト名（例：`ap-study-sync-2026`）を指定する。Googleアナリティクスは不要ならオフでよい。原則として無料の **Spark** プランで始める。
3. プロジェクト概要の「ウェブ（</>）」アプリを登録し、表示された **Firebase SDK の `firebaseConfig`** をコピーする。**Firebase Admin SDKの秘密鍵（サービスアカウントJSON）は絶対に使わない。**
4. 「Authentication」→「Sign-in method」→「メール / パスワード（Email/Password）」を有効にする。メールリンク認証は不要。
5. 「Authentication」→「Settings」→「Authorized domains」に `6thyyvc22t-hash.github.io` を追加する（必要な場合）。`https://` や `/ap-flashcards/` は付けない。
6. 「Firestore Database」→「データベースを作成」。無料プランで選べるリージョンを選択する。**セキュリティルールを公開モードのまま運用しない。**
7. 「Firestore Database」→「ルール（Rules）」に、このリポジトリの [`firestore.rules`](./firestore.rules) の **全文** を貼り付けて **公開（Publish）** する。これにより各ユーザーは自分のUIDの学習記録だけ読み書きできる。

## 2. FirebaseのWeb設定を単語帳へ反映

方法A（最も簡単）：単語帳の「Firebase設定」を開き、コピーした `const firebaseConfig = {...};` を貼り付けて「この端末に設定して接続」を押す。この設定は **その端末だけ** に保存される。設定がうまくいけば「設定ファイルを書き出す」で `firebase-config.json` を取得し、GitHubリポジトリの最上位の同名ファイルに上書きする。

方法B（両端末に一度に適用）：Firebase Web設定の `apiKey`・`authDomain`・`projectId`・`appId` 等を、GitHubリポジトリの `firebase-config.json` に保存する。次回から全端末が同じFirebaseプロジェクトに接続する。**Web設定のAPIキーは公開用のクライアント設定**であり、データへの権限は認証＋Firestoreルールが担う。秘密鍵やFirebaseサービスアカウントは決してコミットしない。

## 3. iPad・iPhoneで同じアカウントにログイン

1. `https://6thyyvc22t-hash.github.io/ap-flashcards/` をSafariで開く。
2. iPadで「初回アカウント作成」を押し、自分のメールアドレスと6文字以上のパスワードを登録する。
3. iPhoneでは **同じメールアドレスとパスワードでログイン**する。認証完了後「✓ クラウドと同期済み」を確認する。
4. どちらかで1問採点し、もう一方のSafariでも正答率・正誤回数が変わるかを試す。通信状態によっては少し遅れて反映される。

## 4. 旧学習記録の移行・トラブル対応

- Firebaseを初めて導入する端末で旧成績が見つかり、クラウドにまだ成績がなければ「この端末の以前の成績を移行」を1回だけ実行する。**両端末の旧記録を自動で足し合わせない**（重複を防ぐため）。クラウド側に記録がある場合は、旧記録を「移行前の成績を保存」でJSONバックアップできる。
- 同じ問題をiPadとiPhoneで採点しても、Firestoreの `increment` と操作IDで合計回数を管理する。二重送信は操作IDで防止する。
- オフラインで採点した操作はSafariのlocalStorageに送信待ちとして保存し、再接続時に再送する。**ブラウザデータ消去・端末故障時には未送信記録が消える**可能性があるため、重要な時はJSONバックアップも取得する。
- 初期問題データ150問と追加・削除は従来どおり `questions.json` でGitHubに管理し、正誤記録のみFirebaseに保存する。問題IDは不変。
- 「学習記録をリセット」「学習記録を読み込む」はクラウドログイン中は**両端末の記録に反映**する。作業前に他端末の未同期の採点を同期させ、必要に応じてバックアップする。
- Firebaseの `firebase-config.json` が未入力（空欄）のうちはクラウド接続しない。サイト自体はローカル学習用として引き続き動作する。

## データ配置・安全性

- **GitHub Pages（公開）**: `index.html`, `app.js`, `cloud-sync.js`, `styles.css`, `questions.json`, `firebase-config.json`
- **Firebase（非公開の成績）**: `users/{uid}/cards/{cardId}`（累積成績）、`users/{uid}/operations/{opId}`（一度だけ加算した操作ID）
- **端末内**: クラウド未送信キュー、問題データの未公開下書き、旧成績のバックアップ
- **Firestoreルール**: `firestore.rules` をFirebase Consoleで公開して初めて有効になる。GitHubにファイルを置くだけでは適用されない。

Firebaseの料金・利用枠はFirebase管理画面の最新情報を確認する。匿名認証でなくメール/パスワード認証を用い、iPadとiPhoneで同じUIDに紐付ける。メールアドレスやパスワードをGitHubリポジトリに入れない。

## 2026-11-23 追加：問題別メモ機能

メモ機能は**各問題IDにひも付く個人用の非公開メモ**です。試験対策の覚え方・苦手理由・補足情報などを最大2,000文字まで登録できます。問題の正解・不正解の採点とは独立して管理し、問題の順序変更や一時削除・復元でもIDが同じならメモは保持します。

### 使用方法

1. 単語帳の各カード下にある「✎ この問題のメモ」に入力する。
2. 入力のたびに端末へ保存される。Firebaseログイン中は、通信可能になるとFirestoreへ同期される。「メモを保存」で即時同期を要求できる。
3. iPhoneとiPadの両方で**同じ単語帳用Firebaseアカウント**にログインすると同じメモが見える。
4. 「メモを削除」はその問題のメモ本文を空にする。クラウドログイン時は他端末にも反映される。
5. 「メモのバックアップ・復元」からJSONの保存・復元が可能。学習成績とメモは別々のバックアップで管理する。
6. ログイン前の端末メモは自動でクラウドに混ぜない。「端末メモを初回同期」で**クラウド側に内容がない問題のみ**を移行する。

### 重要：Firebase Consoleのルール更新が必要

**GitHubへのデプロイだけではメモのクラウド同期は使えません。**

Firebase Console → Firestore Database → 「ルール」で、リポジトリの `firestore.rules` の**全文**を貼り付けて「公開」してください。以前のルールに `/users/{userId}/notes/{cardId}` の許可がないとメモ同期が `permission-denied` になります。学習履歴のルールは変更せずに保持しています。

Firestoreのメモデータは `/users/{uid}/notes/{cardId}` に保存され、**ログイン中の本人のUIDだけ**が読み書きできます。公開の `questions.json` にはメモ本文が入りません。

### 同期・バックアップに関する注意

- 2台で**同じ問題のメモを同時編集した場合は、最後にクラウドへ書き込まれた内容**が残ります（競合解決の履歴はありません）。
- オフライン中の変更は端末の `localStorage` に送信待ちとして保存します。Safariのサイトデータを削除すると未送信メモが失われるため、定期的にメモJSONを保存してください。
- Firebase未ログイン時のメモはその端末内のみです。ログイン後、メモ移行ボタンでクラウドへ取り込めます。
- 「学習記録をリセット」はメモを削除しません。メモを消す場合はメモ欄から削除するか、メモJSONの復元機能で空データに置き換えます。
- 問題自体を「完全削除」しても、そのIDの古いメモがクラウドに残ることがあります。これは学習記録と同様に別管理だからです。

### 追加ファイル

- `memo-sync.js`：Firebase Authと連動するメモの同期モジュール
- `firestore.rules`：メモ専用のアクセスルールを追加した最新全文

## 2026-11-23：問題の追加・編集・削除もFirebaseで自動同期

**公開問題と個人用の変更は分けて管理します。**

- GitHub上の `questions.json` は全利用者共通の問題データです。公開版は2026-11-23時点で207問です。
- 同じFirebaseアカウントでログインした端末からの問題追加・編集・保管・復元・完全削除は、個人用差分 `users/{uid}/deckChanges/{cardId}` に保存・購読され、iPhone・iPad間で反映されます。GitHub公開版の問題は削除されません。
- `deck-sync.js` は、公開問題に個人用差分を重ねて表示します。今後GitHubに新しい問題が公開されても、以前の端末で削除した問題を復活させず、新規公開問題は追加されます。
- 既存の成績 `users/{uid}/cards/{cardId}`・操作ID `operations`・個人メモ `notes` は変更しません。
- 通信できない間に変更したカードは端末のlocalStorageに送信待ちとして保存し、接続回復後に再送します。端末のブラウザデータを削除すると未送信の変更が失われる可能性があります。
- **新機能の利用前にFirebase Consoleで最新の`firestore.rules`全文を公開する必要があります。** GitHubにrulesファイルを保存しただけではFirebase側のアクセス権は変更されません。

### 過去にiPhoneで行ったローカル削除の初回移行

1. 以前削除を行った端末でアプリを開き、Firebaseにログインする。
2. Firebaseルール更新後、問題データがクラウドに読み込まれると「以前の端末下書きをクラウドへ移行」が表示される。
3. 移行候補件数（追加・編集・保管・完全削除）を確認して実行する。
4. 古い下書きは端末内にバックアップしてから移行し、保存が完了するとクラウドへ送信待ち登録される。iPadでも同じFirebaseアカウントで表示する。
5. クラウド側で既に変更のあるIDは上書きしない。**古い下書きで見つからないIDを、勝手に削除したものとはみなさない。**
6. 初回移行後の問題変更は自動同期。未ログインの端末では従来どおりローカル下書き保存。

### 注意

- 個人用で完全削除しても、同じカードIDの学習履歴・メモは別に保存され、ログから自動削除されません。
- 他端末で同じカードを同時編集した場合は最後に書き込まれた内容が優先されます。
- クラウドログイン中の問題JSONの**一括読込は無効化**しました。公開後に追加された問題の誤削除を防ぐためです。ログアウトして端末下書きに読み込んでからログイン・移行してください。
- 問題JSONの書出しは、**表示中の個人用差分も含む版**です。これをGitHubにそのまま上書きすると個人用の削除が全利用者に及ぶため注意。
- Firebase実環境・実機での同期についてはFirebaseルールの更新後に確認してください。
